# การทดสอบชุดแก้ไขความเสถียร

ทดสอบกับฐานข้อมูลแยกจากเว็บจริงก่อน หากใช้ฐานข้อมูลเดียวกัน การรัน SQL มีผลกับข้อมูลจริงด้วย

1. ฐานข้อมูลต้องมี `supabase/schema.sql` และ `supabase/payment-requests.sql` สำหรับฟีเจอร์เรียกเก็บเงินแล้ว
2. รัน `supabase/order-reliability.sql` เพื่อเพิ่มการป้องกันคำขอออเดอร์ซ้ำและดึงออเดอร์ค้างทั้งหมด
3. รัน `supabase/payment-slips.sql` เพื่อเปิดใช้รูปสลิปสำหรับแคชเชียร์
4. เปิดหน้า Deploy Preview ของ PR นี้ แล้วทดสอบส่งออเดอร์ กดซ้ำระหว่างรอผล ออฟไลน์/ลองใหม่ สถานะครัว คิวแคชเชียร์ การดูรายการเก่า แคชเชียร์ถ่ายสลิปและเปิดดู และสร้าง/สแกน QR โต๊ะจริง

การแนบรูปไม่ยืนยันยอดเงินจริง ให้แคชเชียร์ตรวจยอดเงินเข้าก่อนกดยืนยัน และตรวจว่ารูปสลิปและข้อมูลส่วนตัวถูกจำกัดเฉพาะผู้ได้รับสิทธิ์ รูปถูกเก็บในฐานข้อมูลและเพิ่มขนาดไฟล์สำรอง

รหัสคำขอซ้ำจะถูกเก็บในหน่วยความจำหน้าเว็บจนกว่าคำขอนั้นจะสำเร็จ หากปิดหรือรีเฟรชหน้าก่อนทราบผล ผู้ใช้ควรให้พนักงานตรวจออเดอร์ก่อนกดสั่งใหม่ การป้องกันนี้ไม่ผูกสิทธิ์ลูกค้ากับรอบโต๊ะ และ QR ถาวรยังเปิดจากนอกร้านได้
